# MedMLX community

Ask questions, request models, report bugs and share how you use MedMLX.

## Request a model

Use the [model request form](https://github.com/MedMLX/.github/issues/new?template=model-request.yml).
Include the model's repository or paper and your research use case. Links to
weights and license details help us assess a port.

Check [existing requests](https://github.com/MedMLX/.github/issues?q=is%3Aissue%20label%3Amodel-request)
first. If the model is already requested, add your use case to that thread.
Requests do not guarantee a port or a release date.

Requests start with `needs-review`. Maintainers use `planned`, `in-progress`,
`blocked` and `released` to show progress. Follow the issue for updates; a
`planned` label does not set a release date.

## Ask a question

Use [Q&A](https://github.com/MedMLX/.github/discussions/categories/q-a) for
installation, model selection and usage questions. Include the package and
version when asking about a particular runtime. Search existing discussions
before starting a new one.

## Report a bug

Open an issue in the repository for the affected package. The
[model catalog](https://medmlx.org/models/) links to each runtime's repository.

- [API, CLI or MCP server](https://github.com/MedMLX/medmlx/issues/new/choose)
- [Website](https://github.com/MedMLX/medmlx.org/issues/new/choose)

Include the package version, environment, steps to reproduce, expected behavior
and actual behavior. Add the relevant error message when available.

For security vulnerabilities, follow [SECURITY.md](https://github.com/MedMLX/.github/blob/main/SECURITY.md).

## Share your work

Post a research project, tool or workflow in
[Show and tell](https://github.com/MedMLX/.github/discussions/categories/show-and-tell).
Include a link and explain how you use MedMLX.

Requests, issues and discussions are public. A GitHub account is needed to post.
